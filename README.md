## 🎯 the problem

```bash
# you ask an AI: "add auth with refresh tokens"
# it generates 80 lines of code across 3 files.

# it runs without errors. you commit it.
git commit -m "add auth"

# 2 months later — auth is failing in production.
# nobody knows why that token cleanup interval was added.
# including you.
```

**explainit fixes this.**

---

## ✨ how it works

When you commit, explainit checks your actual staged changes (`git diff --cached`) and asks you a quick multiple choice question right in your terminal.

```bash
git add .
git commit -m "add auth"
```

```
🧠 explainit — quick check before commit
──────────────────────────────────────────
  lib/auth.js — 24 lines changed

  What happens when the refresh token expires?

  [1] User gets logged out and must sign in again
  [2] A new refresh token is automatically generated without credentials
  [3] The old token is silently reused forever
  [s] Skip

  Your answer (1/2/3/s): 1

  ✓ Exactly right — expired refresh tokens force re-authentication.

[main 3f2a1] add auth
```

Press 1, 2, or 3. Five seconds. You just verified you understand what's going into your codebase.

> **explainit never blocks your commit.**
> It only checks your understanding. If you're in a rush, hit `s` to skip.

## 🔍 explain your changes (`explainit explain`)

Ever prompt an AI, get back 150 lines of code, and want a quick breakdown of decisions and gotchas before committing it?

```bash
explainit explain
```
```
▸ what changed
──────────────────────────────────────────
◆ Summary: Added JWT refresh rotation and a blacklist check.
◆ What it does:
  → Invalidates old refresh tokens upon rotation so stolen tokens can't be reused.
  → Stores revoked tokens in memory with an expiry timestamp.
◆ Watch out for:
  → Storing tokens in memory means they reset if the server restarts.
```

You can also run it on any specific file:
```bash
explainit explain src/auth.js
```

## ✍️ generate commit messages (`explainit msg`)

Tired of thinking of commit messages? explainit reads your staged diff and writes a clean, conventional commit message for you.

```bash
git commit -m "$(explainit msg)"
# creates: feat(auth): add refresh token rotation and token revocation check
```

## 📦 commands

| command | alias | description |
|---|---|---|
| `explainit setup` | | connect your free Gemini API key |
| `explainit install` | | hook into git (run once per project) |
| `explainit explain` | `exp` | break down staged changes, key decisions, and risks |
| `explainit msg` | `m` | generate a clean commit message from staged diff |
| `explainit quiz [file]` | `q` | manually quiz yourself on changes or a file |
| `explainit score` | `sc` | view your progress, history, and streak |
| `explainit scan <file>` | `s` | preview a file and line stats |

## 🔑 api key — per user, always free

explainit uses a **bring your own key** model.

each user provides their own free Gemini API key. this means:

- ✓ no shared quota — your usage never affects anyone else
- ✓ completely free — 1,500 requests/day is way more than you'll need
- ✓ scales to any number of users
- ✓ your key is stored locally at `~/.explainit/config.json`
- ✓ nothing leaves your machine except direct API calls to Gemini

get your free key at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)

## 🏗️ architecture

```
explainit/
├── bin/
│   └── explainit.js      ← CLI entry point — all commands
├── lib/
│   ├── ai.js             ← Gemini API — questions, explanations, commit messages
│   ├── diff.js           ← reads and parses staged git diffs
│   ├── quiz.js           ← 1-key terminal prompt & answer checker
│   └── scores.js         ← local score storage & streak logic
├── run-quiz.js           ← git hook bridge (auto-created on install)
└── package.json
```
